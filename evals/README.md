# evals/ — likeness · beauty · perf harness

The measured half of ONE HERTZ. Everything the README claims about this site is produced
here, reproducibly, against a rubric frozen at P0. The harness itself is a portfolio
artifact: prompts, raw judge rationales and frame-time arrays ship with every report.

## One command

```sh
npm run build && npm run preview &   # the harness's default target: http://localhost:4173
npm run eval
```

Runs the full round — capture → structural assertions → perf pass → beauty council —
and emits a self-contained HTML report committed at `results/<round>/report.md` (+
`report.html`): side-by-side frame grids, checklist pass/fail, perf traces, judge
verdicts with raw rationales and the exact prompts used.

Partial runs: `npm run eval -- --only capture|assert|perf|judge`.

## Determinism contract

`?eval=1` arms eval mode in the app itself (built in P1): seeded RNG, clock frozen with
the dial at 10:09:30, BPM pinned to 64, ECG phase 0, loader skipped. Capture only begins
after `document.fonts.ready`, the GLB is resident, and 3 consecutive settled rAF frames.
Frame addressing is `(sectionId, localProgress ∈ {0, .25, .5, .75, 1})` through the
section registry — never scroll-pixel offsets — so frames stay stable across layout
changes.

## Gates (summary — rubric.yaml is authoritative)

| Track | Gate |
|---|---|
| Likeness | zero CRITICAL + ≥90% of the 29 binary checklist items |
| Beauty | pairwise vs source: win-or-tie ≥60% overall, no axis <40%, ≥3 axes above source, deception probe passed |
| Perf (desktop) | median ≥55 fps AND p95 ≤22 ms AND ≤5 frames >50 ms per 60 s pass |
| Perf (mobile) | flagship ≥55 fps · mid-tier ≥40 fps (named real device once per round) |

Two-stops ceilings: likeness+beauty 4 rounds, perf 3 rounds — then stop and publish the
deltas (house rule; see `docs/PLAN.md` §6).
