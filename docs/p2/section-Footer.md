## Pitfalls found this lane (inherit)

1. **100svh-solo scroll revert (`gotoSection` + Lenis limit 0).** A solo'd 100svh track is exactly one viewport ⇒ `lenis.limit = 0` ⇒ `gotoSection(name, p)` targets (raw-degenerate) 0.25–0.75 px, the eval settle renders correctly ONCE, then every subsequent engine tick reads the clamped `lenis.scroll = 0` and reverts the frame — screenshots taken after any wait show p=0. Workaround (capture-side, zero core edits): re-pin with a rAF loop registered AFTER gsap's ticker that re-calls `gotoSection` every frame (settleSync is dt=0-pure, so this is idempotent) — see the capture script pattern in this lane's session scratchpad. Proper fix candidate for the evals lane: solo mode could pad the document (or `gotoSection` could bypass Lenis clamping in eval) — flagging, not fixing, since `evals/` is shared.
2. **`Object3D.clone(true)` on the adopted hero is the cheap lineup**: materials/geometry/layers are shared by reference — the emissive dial, KHR texture transforms, and selective bloom all survive cloning with zero re-wiring. Clone AFTER adoption (the screen mesh must already carry the live screen material).
3. The hero's rest tilt is pure rotX(−35°) in world (caseSpace quaternion), so `caseSpace.quaternion.invert()` on a wrapper is the complete face-on correction — no roll fix needed (dial-12 projects exactly to +Y).
4. A 3D row + DOM label rail can be kept aligned at every viewport with one constraint: make camera radius a function of aspect (`radius = k/aspect`) so the row's width fraction is constant, then the label container width is a constant vw.
